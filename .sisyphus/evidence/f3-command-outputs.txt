Source code (src/img2svg/cli.py:305-311):
    device: str = typer.Option(
        "auto",
        "--device",
        help=(
            "Compute backend: auto (default), cpu, cuda, cuda:N, mps, or rocm. "
            "AMD ROCm requires a ROCm PyTorch build (pip install img2svg[amd])."
        ),
    )

Verdict: PARTIAL PASS (functional, but a rendering bug)
- The ROCm install message is present in the help text
- The source code correctly says "pip install img2svg[amd]" (line 310)
- BUT: the rendered help shows "pip install img2svg" — the [amd] portion is stripped
- Root cause: typer/rich treats "[amd]" as a rich markup tag and removes it from the rendered output
- Impact: a user copying the help text and trying to install ROCm would install the wrong extra (the base "img2svg" instead of "img2svg[amd]")
- This is a real user-facing bug, but it is in the rendering layer, not the source. The functional behavior of the CLI is unaffected.

Suggested fix: escape the brackets in the help string. Replace:
    "AMD ROCm requires a ROCm PyTorch build (pip install img2svg[amd])."
with:
    "AMD ROCm requires a ROCm PyTorch build (pip install img2svg\[amd\])."
or use the typer/rich `markup=False` option, or rewrite without brackets (e.g. "(the 'amd' extra of img2svg)"). 

This bug is real but does NOT block the multi-vendor-gpu feature itself — the code path that actually installs the [amd] extra (the install_backend.sh script) is unaffected. The impact is a cosmetic/help-text issue that should be filed as a follow-up.
